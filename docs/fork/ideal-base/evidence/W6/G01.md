# G01: aarch64-linux support, downgraded rather than claimed

Reviewed commit `4df45d719`, published in merge `b88250783` (PR #90).

## The node offers a choice, and this takes the second option

> Build/smoke aarch64-linux or explicitly downgrade its advertised support to
> best-effort.

No workflow has ever built aarch64-linux. `nix.yml` drops it deliberately, so it
is never compiled, smoke-launched, or pushed to Cachix, and a consumer pinning
it always builds ~900 crates from source. Meanwhile `docs/NIX.md` listed all
three flake systems in one flat sentence and the README table paired x86_64 and
aarch64 Linux as equally "Supported by the flake".

Neither this machine nor the remote builder is aarch64-linux, so the build/smoke
branch was not available. **This is a documentation correction, not a support
claim**: the advertised status now matches what CI verifies.

## What did not change, and why

`flake.nix` `systems` is untouched. It is what makes `packages.aarch64-linux.*`
and `checks.aarch64-linux.*` exist as outputs; removing it would delete real
outputs rather than correct a claim. The defect was the claim, so the claim is
what moved.

## The durable part

The matrix moved out of `nix.yml` into `.github/workflows/build-matrix.json`, so
support status is checkable data rather than shell string-building inside a
`run:` block that could only be recovered by regex.
`test_advertised_platform_support_matches_what_ci_builds` then asserts the rule:
every flake system CI does not build must be marked Best-effort, and every
system it does build must not be.

Without that, this fix would have been a one-time doc edit that drifts the next
time the matrix changes.

## Verification

Three controls, each observed failing before the fix:

1. Pre-fix docs fail, quoting the offending sentence.
2. An emptied matrix fails on the vacuity guard rather than passing with nothing
   to check.
3. Renaming the flake `systems` key fails instead of silently parsing to an
   empty set.

Controls 2 and 3 exist because this suite's own failure mode is the program's
defect class: a platform-support test that parses nothing would report support
for everything.

```text
nix shell nixpkgs#python313 --command python3 -m unittest tests.test_nix_distribution_policy
Ran 13 tests in 6.444s
OK
```

## Not verified

- aarch64-linux is still unbuilt and unsmoked. That is the point of the
  downgrade: the repository now says so instead of implying otherwise. If
  aarch64-linux support is ever wanted as a real claim, this node reopens with
  the build/smoke branch.
