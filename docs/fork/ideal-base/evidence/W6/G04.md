# G04 — Windows/FreeBSD not advertised as supported — SATISFIED

**State:** accepted by verification. No code change.

G04 requires proof that Windows and FreeBSD are not advertised as supported
distribution surfaces, that platform code is retained only as explicitly
untested compatibility code, and that no scheduled installer or release smoke
remains required for them.

## No packaged surface

`flake.nix` `systems` is `x86_64-linux`, `aarch64-linux`, plus the darwin
entries; `grep -cE "windows|freebsd" flake.nix` returns **0**. Repository-owned
distribution is Nix-only, so no Windows or FreeBSD package can be produced.

## Claims are explicitly disclaimed

`docs/WINDOWS.md` states plainly: "It does not imply that the independent hard
fork currently distributes a Windows package," and lists **End-user
distribution: Not provided**, **Windows transport: Implemented but untested**,
**Windows CI: Not yet set up**. That is exactly the "explicitly untested
compatibility code" posture G04 asks for.

`docs/BRANCHING.md:165-170` records that Windows CI was removed under issue
\#19 (build/test job, PowerShell syntax job, `cargo-xwin` cross-target check,
Windows release matrix, and `windows-smoke.yml`), retaining `cfg(windows)` code
without claiming or publishing a package.

## No scheduled smoke

`freebsd-smoke.yml` is `on: workflow_dispatch:` only, and states its own fork
policy: "manual dispatch only. The fork ships to macOS + Nix; FreeBSD coverage
is upstream's concern."

The only scheduled workflow mentioning either platform is `fork-ci.yml`, and
the matches there are two comment lines documenting the issue-#19 removal, not
jobs.

## Conclusion

Every clause of G04 is satisfied by shipped state. No work required.
